# T0.6 — Electron shell spike

Date: 2026-09-27
Result: **Measurements complete; performance criteria failed**

Electron satisfies every functional check available on this machine and renders the speaking probe
much closer to the target than Tauri. It still misses both mandatory performance requirements: idle
CPU is far above 5%, and the speaking probe drops frames instead of holding an uninterrupted 60 fps.
T0.7 must apply the written selection rule, record the final shell decision in ADR-0006, and remove
the losing wrapper.

> **This is a shell benchmark, not the Svara desktop UX.** Its control panel, status text, FPS/CPU
> measurements and test buttons exist only to exercise and record the spike. The Phase 2 production
> window must obey the avatar-only invariant in `02-desktop-shell-and-ui.md` §2: only the character
> is visible while idle, with transient interaction UI when needed. No diagnostic panel ships.

## Test build

- Ubuntu 24.04.4 LTS, GNOME 46, current session: X11 (`DISPLAY=:0`, no `WAYLAND_DISPLAY`)
- Intel Iris Xe Graphics (RPL-U), Mesa 25.2.8, direct rendering
- 1920×1080 at 96 dpi (100% scale)
- Electron 44.4.5 with Chromium 144.0.7559.179
- Minified production Vite bundle served locally; Electron user data isolated under
  `/tmp/svara-electron-spike`
- React 19.3, Vite 8.3, Three.js 0.186.1, `@pixiv/three-vrm` 3.5.5
- pixiv `VRM1_Constraint_Twist_Sample`, loaded from an ignored local file; SHA-256
  `12c2b97e95e700783a6a550dc0eee2d7880aeedccef9ae67bc4c5a2f0f2631a2`

The CPU figures sum Electron's browser, zygote, GPU, network, renderer, and persistent audio-service
processes over eleven one-second `pidstat` samples spanning each ten-second page probe. They are
expressed as a percentage of one logical CPU. The settled eight-process tree used approximately
952.6 MiB RSS.

## Criteria

| Speaking holds 60 fps without dropped frames | 59.70 fps, 2 dropped frames, **126.06% aggregate CPU** | **Fail** |

| Ubuntu 26.04 VM functional check | No GNOME 50 VM was available locally | Not measured |
| NVIDIA | No NVIDIA machine is available, as anticipated by the plan | Untested / best effort |

## Comparison available to T0.7

| Measurement | Tauri 2 / WebKitGTK | Electron / Chromium |
|---|---:|---:|
| Idle fps / dropped frames | 28.32 / 0 | **29.90 / 0** |
| Idle aggregate CPU | **63.91%** | 64.40% |
| Speaking fps / dropped frames | 52.53 / 66 | **59.70 / 2** |
| Speaking aggregate CPU | 129.18% | **126.06%** |
| Settled process-tree RSS | **~498 MiB** | ~952.6 MiB |

Neither candidate meets the absolute performance gate on this host. Electron has the materially
better speaking-frame result and similar aggregate CPU; Tauri uses roughly half the memory. The plan
explicitly says to prefer Tauri only if it passes every threshold and otherwise select Electron, but
the decision itself remains scoped to T0.7.

## Functional implementation

The wrapper uses the same shell-independent `@svara/avatar` renderer and production frontend bundle
as T0.5. It provides:

- a transparent, frameless, fixed-size, always-on-top, skip-taskbar `BrowserWindow`;
- Linux window shaping updated from the avatar and diagnostic-panel rectangles;
- native `-webkit-app-region: drag` behavior on the avatar surface;
- a sandboxed renderer and context-isolated preload exposing only validated shape updates and
  structured probe events;
- an isolated temporary Electron profile;
- a WebAudio oscillator test; and
- a launcher that owns and cleans up its local Vite preview process.

## Reproduction

```bash
corepack pnpm install --frozen-lockfile
corepack pnpm --filter @svara/desktop spike:tauri:model # once; shared ignored VRM
GDK_BACKEND=x11 corepack pnpm --filter @svara/desktop spike:electron
```

The host was logged into GNOME on Xorg, so this run cannot be represented as XWayland evidence.
GNOME/Mutter 46 and 50 XWayland correctness remains for T0.10. The missing VM and NVIDIA checks are
recorded limitations rather than inferred passes. They do not alter the local performance outcome.
