# T0.5 — Tauri shell spike

Date: 2026-09-26/27
Result: **Gate failed**

Tauri satisfies the functional checks available on this machine, but the optimized real-VRM run
misses both renderer performance requirements by a wide margin. Under the rule in
`02-desktop-shell-and-ui.md` §1.3, Tauri is not eligible unless it passes every criterion. T0.6 must
now run the identical renderer in Electron so T0.7 has a measured comparison and can record the
final shell decision.

> **This is a shell benchmark, not the Svara desktop UX.** Its control panel, status text, FPS/CPU
> measurements and test buttons exist only to exercise and record the spike. The Phase 2 production
> window must obey the avatar-only invariant in `02-desktop-shell-and-ui.md` §2: only the character
> is visible while idle, with transient interaction UI when needed. No diagnostic panel ships.

## Test build

- Ubuntu 24.04.4 LTS, GNOME 46, current session: X11 (`DISPLAY=:0`, no `WAYLAND_DISPLAY`)
- Intel Iris Xe Graphics (RPL-U), Mesa 25.2.8, direct rendering
- 1920×1080 at 96 dpi (100% scale)
- Tauri 2.11.6, WebKitGTK 2.52.6, Rust 1.98.1
- Release-mode Rust binary and minified production Vite bundle, served locally so the ignored test
  VRM uses the same HTTP load path as Electron
- React 19.3, Vite 8.3, Three.js 0.186.1, `@pixiv/three-vrm` 3.5.5
- pixiv `VRM1_Constraint_Twist_Sample`, loaded from an ignored local file; SHA-256
  `12c2b97e95e700783a6a550dc0eee2d7880aeedccef9ae67bc4c5a2f0f2631a2`

The CPU figures sum the Tauri process and its WebKit network/web children over eleven one-second
`pidstat` samples spanning the ten-second page probe. They are expressed as a percentage of one
logical CPU. The settled process tree used approximately 498 MiB RSS.

## Functional implementation

The same `@svara/avatar` renderer is used by both candidate shells. It has no React or Tauri import
and provides VRM loading, a procedural no-asset fallback, 30/60 fps modes, a vowel-mouth speaking
animation, resizing, and ten-second render probes. The spike page adds a deliberately prominent
diagnostic panel and a thin shell bridge; that panel is excluded from production work in T2.3.

The Tauri wrapper provides:

- a transparent, frameless, fixed-size, always-on-top, skip-taskbar window;
- GTK input shaping updated from the avatar and control-panel rectangles;
- native `start_dragging()` from the avatar surface;
- structured probe events on stdout;
- a WebAudio oscillator test; and
- an Ubuntu 24.04 build/run container plus a pinned, ignored test-model fetcher.

## Reproduction

```bash
corepack pnpm install --frozen-lockfile
corepack pnpm --filter @svara/desktop spike:tauri:build-image
corepack pnpm --filter @svara/desktop spike:tauri:model
GDK_BACKEND=x11 corepack pnpm --filter @svara/desktop spike:tauri
```

The host was logged into GNOME on Xorg, so this run cannot be represented as XWayland evidence.
GNOME/Mutter 46 and 50 XWayland correctness remains for T0.10. This missing check does not change the
Tauri gate outcome because the two mandatory performance checks already failed.

The host release build passed `cargo fmt --check`, locked `cargo check`, and Clippy with warnings as
errors. The Ubuntu 24.04 container definition reached the APT install step, but the Ubuntu mirror
repeatedly dropped package downloads during the final reproduction attempt; the build was stopped
after its configured retries made no progress. This network-only interruption does not affect the
host measurement or the gate, and the same command can be rerun when the mirror is stable.
